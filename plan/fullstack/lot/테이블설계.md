# LOT 테이블 설계 대화 요약

## 1. LOT의 기본 관점

LOT은 단순한 품목 수량이 아니라, 같은 이력과 같은 추적 책임을 공유하는 생산/입고 묶음으로 본다.

예를 들어 밀가루가 100개씩 두 번 입고되었다면, 단순 재고 관점에서는 200개로 합칠 수 있지만 MES 관점에서는 보통 입고 단위가 다르면 `lot1`, `lot2`처럼 분리하는 것이 추적성에 유리하다.

LOT을 크게 합치면 재고 관리는 단순해지지만, 나중에 불량이나 리콜이 발생했을 때 어떤 입고분이 영향을 줬는지 추적하기 어려워진다.

## 2. LOT, STOCK, HISTORY의 역할

LOT은 최초 생성 정보를 보관하는 기준 데이터로 본다.

즉 LOT에는 품목, lot 번호, 최초 생성 수량, 생성일, 최초 상태 같은 값이 들어가며, 이후 수량이 변해도 최초 기준값은 유지하는 방향이 적절하다.

LOT_STOCK은 현재 수량을 나타낸다.

lot당 보통 한 건만 유지하고, 공정 투입이나 생산 산출 등으로 수량이 바뀔 때 같은 데이터를 계속 업데이트한다.

LOT_STOCK_HISTORY는 수량 변경 이력이다.

수량이 생성, 증가, 차감, 조정될 때마다 이력 데이터가 계속 쌓인다. 현재 수량은 LOT_STOCK에서 빠르게 보고, 왜 그렇게 되었는지는 LOT_STOCK_HISTORY에서 추적한다.

따라서 기본 개념은 다음과 같다.

- LOT: 최초 lot 정보
- LOT_STOCK: 현재 lot 수량
- LOT_STOCK_HISTORY: 수량 변경 이력

## 3. HISTORY와 LOG 명칭

lot 수량 차감 이력은 시스템 디버깅용 로그라기보다 업무적으로 조회하고 추적해야 하는 데이터다.

따라서 `LOG`보다는 `HISTORY`라는 명칭이 더 적절하다.

LOG는 보통 API 호출, 에러, 시스템 동작 기록처럼 운영/디버깅 성격이 강하고, HISTORY는 업무 데이터의 변경 내역이라는 의미가 강하다.

## 4. LOT_TRACE 또는 LOT_RELATION의 역할

LOT_TRACE 또는 LOT_RELATION은 lot의 출처와 계보를 기록하는 데이터로 본다.

단순히 현재 수량을 알기 위해서는 STOCK만 있어도 되지만, MES에서는 어떤 산출 lot이 어떤 투입 lot에서 만들어졌는지 추적하는 것이 중요하다.

외부 입고 lot도 trace에 기록할 수 있다. 이 경우 부모 lot이 없는 최초 생성 또는 외부 입고 기록으로 본다.

공정 산출 lot은 해당 공정 실행에서 어떤 투입 lot들을 사용해 만들어졌는지 기록한다.

투입 lot은 여러 개일 수 있으므로, 산출 lot 하나에 투입 lot 여러 개가 연결될 수 있다.

예를 들어 밀가루 lot1과 lot2를 사용해 면 lot3을 만들었다면 trace 관계는 다음처럼 여러 건이 된다.

- lot1 -> lot3
- lot2 -> lot3

정확히 어느 산출물 한 개가 어느 투입 lot에서 나왔는지 알기 어렵다면, 같은 공정 실행에 투입된 lot들을 모두 산출 lot의 영향 lot으로 본다.

## 5. 공정 산출 LOT 생성 시점

공정에서 산출물이 언제 lot으로 생성되는지는 현장 정책에 따라 다르다.

일반적으로는 실제 산출이 확정되는 시점에 lot을 생성하는 것이 안전하다. 아직 실제 수량, 불량 여부, 중단 여부가 확정되지 않았기 때문이다.

하지만 설비가 동작하면서 산출물이 하나씩 나오고, 그때마다 현재 수량을 누적해야 하는 경우에는 공정 시작 또는 승인 시점에 산출 lot을 미리 만들어두는 것이 자연스럽다.

이 경우 미리 만든 lot은 실제 사용 가능한 재고가 아니라 생산 예정 또는 생산 중 lot이다.

초기 수량은 0으로 시작하고, 설비 카운트나 작업 실적이 올라갈 때마다 LOT_STOCK의 현재 수량을 증가시킨다.

공정 종료 시 최종 수량을 확정하고 상태를 완료 또는 사용 가능 상태로 전환한다.

## 6. 산출 LOT의 기준

산출 lot의 기준은 보통 공정 실행 단위로 잡는다.

가장 단순하고 현실적인 기준은 승인 1건당 산출 lot 1개이다.

즉 승인이 내려지면 앞으로 생성될 산출 lot을 미리 만들고, 해당 승인 건에서 발생하는 산출 수량을 그 lot에 누적한다.

예를 들어 밀가루 700개를 투입해 면 70개를 만드는 승인 건이 있다면, 승인 시점에 면 산출 lot을 하나 생성하고 수량 0으로 시작한다.

생산 중 면이 나올 때마다 해당 lot의 수량을 올리고, 생산이 끝나면 최종적으로 70개가 된 lot을 완료 처리한다.

새 lot으로 나누는 기준은 공장마다 다르지만 보통 다음과 같은 조건에서 나눈다.

- 작업지시 또는 승인 건이 바뀌는 경우
- 투입 원재료 lot 조합이 바뀌는 경우
- 설비가 바뀌는 경우
- 레시피 또는 공정 조건이 바뀌는 경우
- 교대조나 날짜 기준으로 나누기로 한 경우
- 생산 중단 후 재시작을 새 배치로 보기로 한 경우
- 검사 판정 단위가 바뀌는 경우

현재 설계 방향에서는 우선 승인 1건당 산출 lot 1개로 잡는 것이 적절하다.

## 7. 최초 LOT 생성 시 필요한 데이터

새 lot이 생기면 최소한 lot 기본 정보와 현재 수량 정보는 같이 생기는 것이 자연스럽다.

수량 추적까지 필요하므로, 생성 시점에 history도 남긴다.

trace를 lot의 출처 기록으로 사용한다면, 외부 입고나 최초 등록 lot도 trace에 생성 출처를 남길 수 있다.

따라서 최초 lot 생성 시에는 다음 흐름이 적절하다.

- LOT 생성
- LOT_STOCK 생성
- LOT_STOCK_HISTORY 생성
- LOT_TRACE 생성

공정 중 산출 lot을 미리 만드는 경우에도 같은 흐름을 사용하되, LOT_STOCK의 초기 수량은 0이고 상태는 생산 예정 또는 생산 중으로 둔다.

## 8. 최종 정리

현재 논의 기준의 최소 안정 구조는 다음 네 가지 역할로 정리된다.

- LOT: 최초 lot 정보
- LOT_STOCK: 현재 수량
- LOT_STOCK_HISTORY: 수량 변경 이력
- LOT_TRACE 또는 LOT_RELATION: lot 생성 출처와 부모-자식 추적 관계

운영 정책은 우선 다음처럼 잡는다.

- 입고 단위가 다르면 lot을 분리한다.
- 승인 1건당 산출 lot 1개를 생성한다.
- 승인 시점에 산출 lot을 미리 만들 수 있다.
- 미리 만든 산출 lot은 수량 0의 생산 예정/생산 중 lot으로 본다.
- 생산 중 발생하는 산출 수량은 해당 lot의 stock에 누적한다.
- 수량이 바뀔 때마다 history를 남긴다.
- 투입 lot이 여러 개면 trace 관계를 여러 건 남긴다.
