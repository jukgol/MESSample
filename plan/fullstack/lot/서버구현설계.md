# LOT 서버 구현 설계

## 1. 구현 목표

현재 WAS의 lot 생성은 `LOT` 테이블 한 건만 생성하는 단순 구조다.

앞으로는 lot 생성, 현재 수량, 수량 이력, lot 추적 관계를 서버 서비스 레벨에서 일관되게 처리한다.

핵심 목표는 다음과 같다.

- lot 생성 시 관련 기준 데이터가 함께 생성되도록 한다.
- lot 수량 변경은 한 서비스 경로를 통해서만 처리한다.
- 수량 변경 시 현재 수량과 이력이 항상 같이 반영되도록 한다.
- 다른 컨트롤러나 서비스가 lot 관련 테이블을 직접 수정하지 않도록 한다.
- 공정 승인, 공정 투입, 공정 산출 등 다른 업무 흐름에서 `LotService`를 주입받아 사용하게 한다.

## 2. 서버 책임 분리

컨트롤러는 요청 검증과 응답만 담당한다.

업무 서비스는 작업지시 승인, 공정 시작, 공정 완료 같은 업무 흐름을 담당한다.

`LotService`는 lot 생성, stock 생성/변경, history 기록, trace 기록을 담당한다.

권장 흐름은 다음과 같다.

```text
Frontend Page
-> Controller
-> 업무 Service
-> LotService
-> SQL Script
-> Database
```

예를 들어 작업지시 승인에서 산출 lot을 미리 생성해야 한다면, `WorkOrderService`가 `LotService`를 호출한다.

공정 투입에서 원자재 lot 수량을 차감해야 한다면, 공정 관련 서비스가 `LotService`의 차감 함수를 호출한다.

컨트롤러나 다른 서비스가 `LOT_STOCK`을 직접 업데이트하지 않는다.

## 3. LOT 생성 흐름

lot 생성은 하나의 공개 함수에서 처리한다.

이 함수는 단순히 `LOT`만 insert하지 않고, 관련 데이터까지 일관되게 생성한다.

기본 생성 흐름은 다음과 같다.

```text
CreateLot
1. LOT 생성
2. LOT_STOCK 생성
3. LOT_STOCK_HISTORY 생성
4. LOT_TRACE 생성
```

입고 lot처럼 즉시 재고가 있는 lot은 초기 stock 수량을 생성 수량으로 둔다.

공정 승인 시점에 미리 만드는 산출 lot은 초기 stock 수량을 0으로 둔다.

이때 lot 상태는 생산 예정 또는 생산 중 상태로 둔다.

## 4. LOT 수량 변경 흐름

lot 수량 변경은 전용 함수를 통해서만 처리한다.

수량 변경 함수는 증가, 차감, 조정에 모두 사용할 수 있도록 설계한다.

개념 흐름은 다음과 같다.

```text
ChangeLotStock
1. 현재 LOT_STOCK 조회
2. 변경 후 수량 계산
3. 수량 부족 또는 음수 여부 검증
4. LOT_STOCK 업데이트
5. LOT_STOCK_HISTORY 추가
```

차감 전용 함수와 증가 전용 함수는 내부적으로 공통 변경 함수를 호출하도록 둘 수 있다.

```text
DecreaseLotStock -> ChangeLotStock
IncreaseLotStock -> ChangeLotStock
AdjustLotStock   -> ChangeLotStock
```

중요한 규칙은 `LOT_STOCK`이 바뀌면 반드시 `LOT_STOCK_HISTORY`가 같이 쌓여야 한다는 점이다.

## 5. 트랜잭션 기준

lot 생성, stock 생성, history 생성, trace 생성은 하나의 트랜잭션으로 처리한다.

수량 변경도 stock update와 history insert가 하나의 트랜잭션으로 묶여야 한다.

예를 들어 stock은 100에서 70으로 변경되었는데 history insert가 실패하는 상태가 생기면 안 된다.

따라서 WAS의 현재 SQL 실행 구조에서 트랜잭션 지원 방식을 확인하고, 필요하면 여러 SQL을 하나의 DB connection/transaction 안에서 실행할 수 있는 서비스 메서드를 추가한다.

## 6. LotService 공개 함수 후보

`LotService`에는 외부 업무 서비스가 사용할 수 있는 의도 중심 함수들을 둔다.

후보는 다음과 같다.

```text
CreateLotAsync
입고 lot 또는 일반 lot 생성

CreateProductionLotAsync
공정 승인 시 산출 예정 lot 생성

IncreaseLotStockAsync
생산 산출, 입고 추가 등으로 수량 증가

DecreaseLotStockAsync
공정 투입, 출하, 폐기 등으로 수량 차감

AdjustLotStockAsync
재고 실사 또는 관리자 보정

CompleteProductionLotAsync
생산 중 lot을 완료 상태로 전환

CreateLotTraceAsync
lot 출처 또는 부모-자식 관계 기록
```

외부 서비스는 SQL 이름이나 테이블 구조를 몰라도 되며, lot에 대해 하려는 업무 의도만 `LotService`에 전달한다.

## 7. 공정 승인 시 산출 LOT 생성

현재 정책은 승인 1건당 산출 lot 1개를 생성하는 방향으로 잡는다.

승인 시점에는 아직 실제 산출 수량이 없으므로 stock 수량은 0으로 시작한다.

이 lot은 사용 가능한 재고가 아니라 생산 예정 또는 생산 중 lot이다.

개념 흐름은 다음과 같다.

```text
작업지시 또는 공정 승인
-> 산출 item 확인
-> 산출 lot 번호 생성
-> LOT 생성
-> LOT_STOCK 수량 0 생성
-> LOT_STOCK_HISTORY에 생성 이력 기록
-> LOT_TRACE에 승인/공정 실행 출처 기록
```

공정 중 설비 카운트나 작업 실적이 발생하면 같은 산출 lot의 stock 수량을 증가시킨다.

공정 종료 시 최종 수량을 확정하고 lot 상태를 완료 또는 사용 가능 상태로 변경한다.

## 8. 투입 LOT와 TRACE 처리

투입 lot은 여러 개일 수 있다.

따라서 산출 lot에 투입 lot 하나만 저장하는 방식은 피한다.

산출 lot 하나에 여러 투입 lot이 연결될 수 있도록 trace 데이터를 여러 건 생성한다.

예를 들어 밀가루 lot1과 lot2를 사용해 면 lot3을 만들었다면 trace는 다음처럼 기록한다.

```text
lot1 -> lot3
lot2 -> lot3
```

정확히 어느 산출물 하나가 어느 투입 lot에서 나왔는지 알 수 없는 경우에는, 해당 공정 실행에 투입된 모든 lot을 산출 lot의 영향 lot으로 본다.

## 9. 다른 서비스에서의 사용 방식

작업지시 승인 서비스는 산출 예정 lot 생성이 필요할 때 `LotService.CreateProductionLotAsync`를 호출한다.

공정 투입 서비스는 원자재 lot 차감이 필요할 때 `LotService.DecreaseLotStockAsync`를 호출한다.

공정 산출 서비스는 생산 수량 누적이 필요할 때 `LotService.IncreaseLotStockAsync`를 호출한다.

공정 완료 서비스는 산출 lot 완료 처리가 필요할 때 `LotService.CompleteProductionLotAsync`를 호출한다.

이렇게 하면 lot 정책이 바뀌어도 대부분 `LotService` 안에서만 수정할 수 있다.

## 10. 기존 코드 기준 확인 사항

현재 관련 코드는 다음 위치에 있다.

- `src/WAS/Controllers/App/LotController.cs`
- `src/WAS/Services/App/ILotService.cs`
- `src/WAS/Services/App/LotService.cs`
- `src/WAS/Data/Scripts/Queries/App/Lot/CREATE_LOT.sql`
- `src/Shared/Models/App/LotModels.cs`
- `src/WAS/Data/Scripts/Migrations/0004_CreateTable_LOT.sql`

현재 `CreateLotAsync`는 `LOT` 테이블만 insert한다.

앞으로 구현 시에는 이 흐름을 확장하거나, 기존 API 호환을 유지하면서 내부적으로 통합 생성 함수를 호출하게 변경한다.

## 11. 구현 순서 제안

1. 신규 테이블 migration 추가
2. 신규 SQL script 추가
3. DTO/model 추가 또는 확장
4. `ILotService`에 lot 생성/stock 변경/trace 함수 추가
5. `LotService`에 트랜잭션 기반 생성/변경 로직 구현
6. 기존 `CreateLotAsync`가 신규 생성 흐름을 사용하도록 변경
7. 작업지시 승인 또는 공정 서비스에서 `LotService` 호출 연결
8. WAS 빌드로 swagger 생성 및 컴파일 확인

## 12. 핵심 원칙

- lot 생성은 한 경로로 처리한다.
- lot 수량 변경은 한 경로로 처리한다.
- stock 변경과 history 기록은 분리되어 실패하면 안 된다.
- 다른 서비스는 lot 테이블을 직접 수정하지 않는다.
- 승인 1건당 산출 lot 1개를 기본 정책으로 한다.
- 공정 승인 시 산출 lot을 미리 만들 수 있다.
- 미리 만든 lot은 수량 0의 생산 예정/생산 중 lot으로 취급한다.
- 투입 lot이 여러 개면 trace도 여러 건 만든다.
