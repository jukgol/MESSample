# 기술 및 라이브러리 명세서

## 1. 프로젝트 구성 개요

이 프로젝트는 MES 샘플 시스템으로, 백엔드 WAS, 프론트엔드, Oracle DB, 테스트 도구로 구성되어 있다.

| 영역 | 위치 | 주요 기술 |
| --- | --- | --- |
| 백엔드 WAS | `src/WAS` | ASP.NET Core 8, Dapper, Oracle Managed DataAccess, DbUp, JWT, SignalR, Swagger |
| 공통 모델 | `src/Shared` | .NET 8 Class Library, DTO/Model 공유 |
| 프론트엔드 | `src/Frontend` | React 19, TypeScript, Vite, Axios, Zustand, React Router, SignalR Client |
| DB | `src/WAS/Data/Scripts` | Oracle SQL, Migration SQL, Query SQL, Procedure SQL |
| 테스트 도구 | `src/TestTool` | Python 3.11+, Streamlit |
| 실행 환경 | 루트, `src/WAS/Dockerfile` | Docker Compose, Oracle Database Free, .NET Docker 이미지 |

## 2. 백엔드 WAS 기술

### ASP.NET Core 8

- 사용 위치: `src/WAS/WAS.csproj`, `src/WAS/Program.cs`
- 용도:
  - REST API 서버 구현
  - Controller 기반 API 엔드포인트 제공
  - DI 컨테이너를 통한 서비스 등록
  - 정적 파일 제공
  - Swagger/OpenAPI 문서 생성
  - SignalR Hub 제공

프로젝트는 `Microsoft.NET.Sdk.Web` 기반이며 Target Framework는 `net8.0`이다.

### ASP.NET Core Controller API

- 사용 위치: `src/WAS/Controllers`
- 용도:
  - MES 업무 기능을 HTTP API로 제공
  - 예: Item, ItemType, BOM, Lot, WorkOrder, ProcessMaster, ProcessStep, MRP, History, Auth, Admin API
- 주요 라우팅 방식:
  - `[ApiController]`
  - `[Route("api/[controller]")]`
  - `[HttpGet]`, `[HttpPost]`, `[HttpPut]`, `[HttpDelete]`

### Dapper

- 패키지: `Dapper` 2.1.72
- 사용 위치:
  - `src/WAS/Services/ScriptExecutor.cs`
  - `src/WAS/Services/ProcedureRegistration.cs`
  - 각 업무 서비스 클래스
- 용도:
  - Oracle DB에 SQL을 실행하는 경량 ORM
  - SQL 파일 기반 쿼리를 객체로 매핑
  - `QueryAsync<T>`, `ExecuteAsync`, `ExecuteScalarAsync` 사용
  - `Program.cs`에서 `Dapper.DefaultTypeMap.MatchNamesWithUnderscores = true` 설정으로 DB 컬럼명과 C# 속성명 매핑 보완

### Oracle Managed DataAccess

- 패키지: `Oracle.ManagedDataAccess.Core` 23.26.200
- 사용 위치:
  - `src/WAS/Data/dbconnect.cs`
  - `src/WAS/Services/ScriptExecutor.cs`
- 용도:
  - Oracle DB 연결
  - OracleConnection 생성
  - OracleException 처리
  - OracleParameter 처리

DB 연결 문자열은 `src/WAS/appsettings.json`의 `ConnectionStrings:OracleDb`에 정의되어 있다.

### DbUp Oracle

- 패키지: `dbup-oracle` 6.2.0
- 사용 위치:
  - `src/WAS/Data/DatabaseMigrator.cs`
  - `src/WAS/Data/Scripts/Migrations/*.sql`
- 용도:
  - WAS 시작 시 Oracle DB 마이그레이션 자동 실행
  - `Data/Scripts/Migrations`의 SQL 파일을 Embedded Resource로 포함
  - `DeployChanges.To.OracleDatabaseWithDefaultDelimiter(...)`로 Oracle 대상 마이그레이션 구성
  - `PerformUpgrade()`로 미적용 마이그레이션 실행

즉, DB에서 WAS로 마이그레이션을 관리하는 핵심 라이브러리는 `DbUp + dbup-oracle`이다.

### SQL 파일 기반 Query/Procedure 구조

- 사용 위치:
  - Migration: `src/WAS/Data/Scripts/Migrations`
  - Query: `src/WAS/Data/Scripts/Queries`
  - Procedure: `src/WAS/Data/Scripts/Procedures`
- 용도:
  - C# 코드에 SQL을 직접 길게 넣지 않고 `.sql` 파일로 분리
  - `ScriptExecutor`가 Query SQL 파일을 읽어서 Dapper로 실행
  - `ProcedureRegistration`이 Procedure SQL 파일을 서버 시작 시 DB에 배포

### JWT 인증

- 패키지:
  - `Microsoft.AspNetCore.Authentication.JwtBearer` 8.0.*
  - `System.IdentityModel.Tokens.Jwt` 8.17.0
- 사용 위치:
  - `src/WAS/Extensions/IdentityServiceExtensions.cs`
  - `src/WAS/Services/Auth/AuthService.cs`
  - `src/WAS/Controllers/Auth`
- 용도:
  - 로그인 성공 시 JWT 토큰 발급
  - `[Authorize]`로 API 보호
  - Role/Permission 기반 권한 처리
  - SignalR Hub 접속 시 query string의 `access_token`도 인증 토큰으로 처리

### Permission 기반 Authorization

- 사용 위치:
  - `src/WAS/Authorization`
  - `src/WAS/Attributes/HasPermissionAttribute.cs`
  - `src/WAS/Common/Constants/Permissions.cs`
  - 각 Controller의 `[HasPermission(...)]`
- 용도:
  - 역할별 권한 확인
  - 메뉴/기능 단위 접근 제어
  - `PermissionPolicyProvider`, `PermissionAuthorizationHandler`로 커스텀 권한 정책 처리

### SignalR

- 사용 위치:
  - 서버: `src/WAS/Hubs/ProcessMonitoringHub.cs`
  - 서버 등록: `src/WAS/Program.cs`
  - 프론트 연결: `src/Frontend/src/features/process/monitoring/hooks/useProcessMonitoring.ts`
- 용도:
  - 공정 모니터링 화면의 실시간 갱신
  - Hub 경로: `/hubs/process-monitoring`
  - 인증 필요: `[Authorize]`

### Swagger / OpenAPI

- 패키지: `Swashbuckle.AspNetCore` 6.6.2
- 사용 위치:
  - `src/WAS/Program.cs`
  - `src/WAS/WAS.csproj`
- 용도:
  - API 문서 생성
  - 개발 환경에서 Swagger UI 제공
  - 빌드 후 `src/api/swagger.json` 생성

`WAS.csproj`의 `GenerateSwagger` Target이 빌드 후 다음 명령을 실행한다.

```text
dotnet tool run swagger tofile --output ../api/swagger.json ...
```

### Bogus

- 패키지: `Bogus` 35.6.5
- 사용 위치:
  - 더미 데이터 생성 관련 서비스에서 사용되는 용도
- 용도:
  - 테스트/시나리오용 가짜 데이터 생성
  - 예: 품목, Lot, 공정 데이터 등의 샘플 데이터 구성

### LoggingProxy / DispatchProxy

- 사용 위치:
  - `src/WAS/Proxies/LoggingProxy.cs`
  - `src/WAS/Extensions/ServiceCollectionAppExtensions.cs`
  - `src/WAS/Extensions/ServiceCollectionAdminExtensions.cs`
- 용도:
  - 서비스 인터페이스에 프록시를 씌워 AOP 방식의 로깅 처리
  - `[Log]` Attribute 기반 메시지 처리
  - 예외 발생 시 공통 로깅

### CORS

- 사용 위치: `src/WAS/Extensions/CorsServiceExtensions.cs`
- 용도:
  - 프론트엔드와 WAS 간 API 호출 허용
  - 정책명: `AllowAll`
  - 허용 메서드: `GET`, `POST`, `OPTIONS`

### HttpClient

- 사용 위치: `src/WAS/Extensions/ServiceCollectionExtensions.cs`
- 용도:
  - 서버 내부에서 외부 HTTP 호출이 필요한 경우를 위한 `AddHttpClient()` 등록

## 7. API 생성 흐름

이 프로젝트의 API 타입 생성 흐름은 다음과 같다.

1. WAS 빌드
   - 명령: `dotnet build src/WAS/WAS.csproj`
   - 결과: `src/api/swagger.json` 생성

2. 프론트 API 클라이언트 생성
   - 위치: `src/Frontend`
   - 명령: `npm run generate-api`
   - 결과: `src/Frontend/src/api`에 TypeScript API 클라이언트 생성

3. 프론트 화면에서 API 사용
   - Axios 기반 생성 클라이언트 사용
   - Vite 개발 서버에서 `/api` 요청을 WAS `localhost:5175`로 프록시
