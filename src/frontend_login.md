# MES 인증 및 로그인 시스템 시퀀스

본 문서는 MES 시스템의 프론트엔드 인증 및 로그인 방어 로직의 흐름을 정리합니다.

## 인증 시퀀스 (Authentication Sequence)

1.  **진입 단계**: 사용자가 앱에 접속하면 `App.tsx`가 루트 경로(`/`)를 자동으로 로그인 페이지(`/login`)로 안내합니다.
2.  **로그인 상태 확인**: 로그인 페이지는 로컬 스토리지에 토큰이 이미 있는지 확인하고, 있다면 "1초 후 이동" 메시지를 보여주며 대시보드로 보냅니다.
3.  **사용자 로그인**: 토큰이 없다면 아이디/비밀번호를 입력받아 서버 API로 인증을 요청하고, 성공 시 토큰과 사용자 정보를 저장소에 보관합니다.
4.  **대시보드 보호(AuthGuard)**: 모든 대시보드 접근은 `AuthGuard`가 가로막아, 서버에 가벼운 요청을 보내 현재 토큰이 진짜 유효한지 최종 검문합니다.
5.  **인증 실패 감시(Interceptor)**: 앱 사용 중 언제라도 서버에서 "401 Unauthorized(인증 만료)" 에러가 돌아오면, API 인터셉터가 이를 즉시 낚아챕니다.
6.  **강제 로그아웃 및 복귀**: 만료가 확인되면 인터셉터가 저장소의 인증 정보를 지우고 브라우저를 로그인 페이지로 강제 리다이렉트 시킵니다.
7.  **최종 진입**: 모든 검문을 무사히 통과한 경우에만 사용자는 실제 대시보드 화면과 품목 리스트 등의 데이터를 볼 수 있습니다.

## 주요 구성 요소
- **AuthGuard.tsx**: 보호된 라우트 진입 시 토큰 유효성 선제 검사
- **api/client.ts**: Axios Interceptor를 통한 전역 401 에러 감시
- **useAuthStore.ts**: Zustand + Persist를 이용한 인증 상태 유지
